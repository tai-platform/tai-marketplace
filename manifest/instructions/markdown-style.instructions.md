# Markdown style

- Start with one H1 that names the thing, then a one sentence purpose.
- One idea per paragraph, short sentences, active voice. Lead with the answer.
- Headings are sentence case and never skip a level.
- Use a table for comparisons, a numbered list for ordered steps, a bullet list for the rest.
- Every code block has a language tag. Commands are copy pasteable and show no prompt symbol.
- Link to the source of truth instead of repeating it. Use relative links inside the repository.
- Name things exactly as they appear in code, in backticks.
- No marketing language, no filler such as "simply" or "easily", no emojis, no decorative punctuation.
- State versions and limits explicitly. Never write "latest" without saying what that means.
- Keep lines readable: wrap prose at a sensible length or one sentence per line, consistently within a file.
